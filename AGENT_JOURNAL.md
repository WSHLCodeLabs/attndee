# Attndee — Agent Development Journal & Engineering Log

This development journal tracks architectural context, design tradeoffs, security evaluations, and engineering milestones for the **Attndee** project, maintained in accordance with `GEMINI.md` standards.

## 🏛️ System Overview & Architecture Principles

Attndee is a production-grade, contactless classroom attendance verification system designed for universities and higher-education institutions (specifically optimized for Kasetsart University's **myKU** workflow).

* **Frontend Stack**: Next.js 16 (App Router), React 19, Tailwind CSS v4, Lucide React
* **Backend Stack**: Supabase (PostgreSQL, Row Level Security, Realtime WebSockets)
* **Design Philosophy**: Minimalist black, white, and electric blue (`#0051fc` / `blue-600`), zero-install web experience for students, and frictionless one-click workflows for instructors.

## ⏳ Temporal Awareness & Context Log

### 1. Past Decisions & Audit Findings

During the architectural audit and pre-production refactoring passes, several critical vulnerabilities and architectural bugs were uncovered and resolved:

#### A. Broken XLSX Export Index Bug (Off-by-One / Misaligned Rows)
* **Root Cause**: The raw `.xlsx` files generated by myKU contain non-uniform metadata headers (university logo, faculty information, semester, report generation timestamp) spanning rows 1 to 7. Initial export implementations wrote check-in status directly into row indices matching the checkin array length, which created catastrophic row misalignment (e.g., student A received student B's attendance score).
* **Fix & Decision**: Designed a resilient myKU header-detection parser and key-based row locator. Instead of array index writing, the exporter reads the original workbook, indexes student positions by their exact 10-digit student ID (`^[0-9]{10}$`), and writes values into the matching row.

#### B. Room Auto-Deletion & Ephemeral Data Loss
* **Root Cause**: Early drafts utilized ephemeral room cleanup that immediately purged room rows and cascaded deletions across check-in logs as soon as the instructor navigated away from the QR screen. This prevented instructors from reviewing absences or re-exporting lost files.
* **Fix & Decision**: Transitioned to soft-closing state machines (`status: 'active' | 'closed'`). Room records and associated student check-ins remain preserved in Supabase, enabling Post-Session Summaries, manual check-in overrides, and persistent audits.

#### C. Multi-Browser & Incognito Spoofing Risk (Proxy Check-in)
* **Root Cause**: Reliance on simple `localStorage` keys allowed students to open Incognito/Private tabs or switch between Safari and Chrome on a single smartphone to check in for absent peers.
* **Fix & Decision**: 
  1. **Attndee. Pass™ 7-Day Cooldown**: Once a student binds their 10-digit student ID to an Attndee Pass on an origin, changing the identity is locked for 7 days.
  2. **Device & Canvas Fingerprinting**: Generates hardware-derived signatures (GPU renderer, screen metrics, canvas noise) to detect when multiple check-ins originate from the same physical handset regardless of private browsing mode.

#### D. vConsole Bundling in Production
* **Root Cause**: The mobile debugging library `vconsole` was unconditionally imported in client bundles, injecting an overlay button into student viewports and degrading DOM rendering performance.
* **Fix & Decision**: Completely stripped or strictly gated `vconsole` behind non-production environment checks (`process.env.NODE_ENV === 'development'`).

### 2. Present Architecture & Core Capabilities

#### A. KU XLSX Auto-Parser & Numeric `1`/`0` Exporter
* **Parser**: Instructors drag and drop `.xlsx` registration rosters exported directly from myKU. Attndee detects the subject code, course title, and section number, discarding header rows without requiring manual spreadsheet cleaning.
* **Excel SUM Ready**: Attendance columns are marked strictly with numeric `1` (Present) and `0` (Absent). Instructors can write `=SUM(G5:Z5)` in Microsoft Excel or Google Sheets to calculate semester attendance scores instantly without string replacement or macro scripts.

#### B. 30-Second TOTP Rolling QR with Grace Window
* Dynamic QR codes are generated using HMAC-SHA1 Time-based One-Time Passwords (TOTP) with an ephemeral secret per session.
* QR codes rotate every 30 seconds to invalidate captured screenshots.
* Includes an intelligent **Grace Window** (±1 time interval, up to 60s window) to accommodate mobile GPS acquisition latency and cellular connection lag without rejecting valid students.

#### C. Post-Session Summary & Manual Override
* Upon closing a session, the instructor is presented with a Post-Session Absentee Dashboard listing all absent enrolled students.
* Instructors can manually override attendance for individual students (e.g., student battery depletion, network failure, or certified medical leave) with a single click prior to triggering the final XLSX export.

#### D. Shared Production UI Components
* **`components/Toast.tsx`**: Lightweight, accessible notification toast system with custom hook (`useToast`), auto-dismiss timer (default 4000ms), and custom Lucide icons for `success`, `error`, `warning`, and `info`.
* **`components/ConfirmModal.tsx`**: Accessible modal replacement for native browser dialogs with backdrop blur, keyboard navigation (ESC handling), and variant-specific action accents.
